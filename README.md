# FLEXUS

Unity-проєкт, який демонструє мій підхід до побудови невеликої, але масштабованої gameplay-системи: керування персонажем, взаємодія з автомобілем, перемикання станів гри, модульна фізика авто та конфігурація через data-driven підхід.

## Що реалізовано

- Керування персонажем від третьої особи з окремою логікою руху, взаємодії та камери.
- Вхід/вихід з автомобіля з перемиканням глобального стану гри та input action maps.
- Data-driven спавн автомобілів через `CarDefinition` і factory-підхід.
- Модульна архітектура авто: physics, audio, VFX, interaction, occupancy, UX.
- `CarStateMachine` для керування життєвим циклом авто: порожнє авто, вхід, керування, вихід.
- Visual feedback для interactable-об'єктів.
- EditMode і PlayMode тести для ключової логіки.

## Чому цей проєкт показовий

- Архітектура не зводиться до `MonoBehaviour`-скриптів "на сцені": логіка розділена на окремі ролі, сервіси й фасади.
- Залежності інжектяться через Zenject/Extenject, а не створюються хаотично в рантаймі.
- Нова машина додається через конфіг і prefab, без переписування фабрики або спавнера.
- Системи ізольовані настільки, щоб їх можна було окремо тестувати й розширювати.
- Для конфігів використаний покращений editor workflow через Odin Inspector, щоб прискорити ітерації й зменшити кількість помилок на даних.

## Технічний стек

- Unity 6 `6000.0.65f1`
- C#
- Zenject / Extenject
- New Input System
- Cinemachine
- UniTask
- Odin Inspector
- NUnit для EditMode / PlayMode тестів

## Архітектурні рішення

### 1. Composition Root + Dependency Injection

Глобальні залежності збираються через installers, а окремі сутності мають власні контексти. Це дозволяє:

- явно контролювати життєвий цикл об'єктів;
- тримати код слабко зв'язаним;
- легше розширювати функціональність без каскадних змін.

### 2. Facade + модульність

Автомобіль організований не як один великий клас, а як набір окремих модулів:

- core orchestration;
- physics modules;
- VFX modules;
- audio modules;
- interaction/occupancy logic.

Такий підхід спрощує підтримку, локалізує зміни і зменшує ризик регресій.

### 3. Data-driven конфігурація

Автомобілі створюються через `CarDefinition` + `CarData`, а фабрика працює з ID. Це дає:

- легке додавання нових машин;
- відокремлення даних від логіки;
- передбачуване масштабування контенту.

### 4. Керування станом гри

`GameStateController` централізовано перемикає гру між режимами `Player` і `Car`, оновлюючи відповідні input maps. Це прибирає дублювання умов по всьому коду й робить поведінку прозорою.

### 5. Тестованість

У проєкті є окремі EditMode і PlayMode тести для перевірки модулів та базової поведінки view/model взаємодії. Для невеликого тестового завдання це навмисний акцент: я закладаю перевіряємість навіть у компактних проєктах.


## Як запустити

1. Відкрити проєкт у Unity 6 (`6000.0.65f1`).
2. Запустити сцену `Boot`.
3. Після старту:

- `WASD` - рух персонажа / керування авто
- `Mouse` - огляд
- `Shift` - спринт
- `E` - сісти в авто / вийти з авто
